## Estado de los contratos

La [referencia API](/reference) se genera únicamente desde archivos OpenAPI YAML versionados en `docs/`. Todos están en estado **borrador**: describen la implementación revisada, pero ante una diferencia prevalece el código y el contrato debe corregirse en el mismo cambio.

| Servicio | Contrato | Alcance |
| --- | --- | --- |
| Auth Service | `docs/auth/contracts/auth-service-v1.yaml` | Perfil, directorio administrativo, contextos académicos y catálogo. |
| BFF | `docs/bff/contracts/bff-v1.yaml` | Sesión, administración, Data Warehouse y fachadas de OLAP y Predicción. |
| DW Control | `docs/dw/contracts/dw-control-service-v1.yaml` | Cierres académicos y ejecuciones ETL. |
| OLAP Service | `docs/olap/contracts/olap-service-v1.yaml` | Subconjunto de Saiku que usan los portales: descubrimiento, consultas y administración. |
| Prediction Service | `docs/prediction/contracts/prediction-api-v1.yaml` | Inferencia, lotes, publicaciones y entrenamiento. |

### Qué no cubren

- **Auth Service**: los endpoints de demostración y las rutas internas servidor a servidor no se publican. Springdoc puede generar el esquema en ejecución con `AUTH_API_DOCS_ENABLED=true` para contrastarlo.
- **OLAP Service**: las rutas de IA, repositorio, apps, dashboards y GraphQL de Saiku siguen documentadas en `olap-service/docs/`. Los cuerpos `ThinQuery` y `QueryResult` se describen solo a nivel de propiedades estables.
- **BFF**: el esquema GraphQL se describe en `docs/graphql/bff-analytics.md`.
- **ETL Apache Hop**: no expone un API HTTP; su operación se explica en [Integración de datos](/docs/integracion-de-datos).

## Cómo se publican en el portal

El portal no lee `docs/` directamente: `scripts/sync-openapi.mjs` copia los contratos a `apps/docs-portal/openapi/` para que estén disponibles en la imagen Docker, cuyo contexto es `dss-monorepo/`.

1. Edita el contrato en `docs/<servicio>/contracts/`.
2. Ejecuta `bun nx run @dss-monorepo/docs-portal:sync-openapi` (también corre antes de `dev` y `build`).
3. Confirma en el mismo commit el YAML de `docs/` y su copia en `openapi/`. `bun nx run @dss-monorepo/docs-portal:check-openapi` falla si la copia está desactualizada.

## Ejemplos

Cada operación muestra ejemplos en cURL, JavaScript y Python. Si el contrato declara un ejemplo de solicitud, se usa tal cual; si no, el portal genera una **plantilla** con valores de tipo (`<texto>`, `0`) a partir del esquema y lo indica. Las respuestas solo muestran ejemplos declarados en el YAML: el portal no inventa payloads.

<Callout title="Fuente de verdad">
  Añade ejemplos de request y response al contrato solo después de verificarlos contra la implementación o fixtures autorizados, sin datos personales.
</Callout>
